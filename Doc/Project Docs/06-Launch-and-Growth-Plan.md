# Launch and Growth Plan

## Build-in-public strategy

- Publish one concrete update every 3 days.
- Share failures and fixes, not only wins.
- Always include one visual artifact (dashboard clip, report screenshot, architecture snippet).

## 4-week content rhythm

### Week 1

- Post problem narrative and prototype goal.
- Show first endpoint test flow.

### Week 2

- Show live dashboard stream.
- Show one real bug found by semantic analysis.

### Week 3

- Show Swagger mode and multi-endpoint scan.
- Show report sharing link experience.

### Week 4

- Launch thread with demo video and repo.
- Publish technical breakdown post.

## Launch checklist

- README includes:
  - problem statement,
  - architecture,
  - quickstart,
  - screenshots,
  - limitations and safety policy.
- Public demo is stable on staging API samples.
- Abuse guardrails verified.
- Cost limits verified.

## Early growth loop

- Every bug found by users becomes:
  - a fix,
  - a test case,
  - a short educational post.
- Capture testimonials from first 10 users.
- Track activation metric: first completed run within 10 minutes.

## MVP KPIs

- Time to first result <= 2 minutes.
- Report share rate >= 20%.
- Week-1 to week-2 retention >= 25% for trial users.
- False-positive complaint rate < 15%.
